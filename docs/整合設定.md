# 外部工具 / AI 客戶端串接設定

**繁體中文** ｜ [English](整合設定.en.md) ｜ [日本語](整合設定.ja.md)

> 對應規畫書第 10 節。

所有客戶端共用同一組資訊：

| 項目 | 值 |
|---|---|
| Base URL | `http://<AI主機IP>:8787/v1` |
| API Key | 每位人員自己的 `agi-bar-xxxxxxxx` |
| 模型名稱 | `agi-bar-default`（或 `agi-bar-fast` / `agi-bar-long`） |

**模型名稱是別名，不是後端真實模型。** Gateway 會依管理員為該人員設定的
Model Routing Chain 自動選擇後端；使用者不需要、也看不到實際模型名稱。

**先跑自動驗證，再動手設定工具**。腳本會把各客戶端實際會送的請求打一遍，
在你花時間設定之前就找出會卡住的地方，並印出可直接貼上的設定：

```bash
node tests/integration/client-compat.mjs --url http://192.168.1.100:8787 --key agi-bar-你的Key
```

說明見 [tests/integration/README.md](../tests/integration/README.md)。

或手動確認 Key 可用：

```bash
curl http://192.168.1.100:8787/v1/models -H "Authorization: Bearer agi-bar-你的Key"
```

## Cursor

程式開發 IDE，透過 AGI BAR API 使用本地模型。

1. `Settings` → `Models` → `OpenAI API Key`
2. 勾選 **Override OpenAI Base URL**，填入 `http://<AI主機IP>:8787/v1`
3. API Key 欄位填入 `agi-bar-xxxxxxxx`
4. 在自訂模型清單新增 `agi-bar-default`，並停用其他雲端模型
5. 按 **Verify** 確認連線

> Cursor 的部分功能（Tab 補全、Composer 的某些模式）走 Cursor 自家伺服器，
> 不會經過 AGI BAR。需要完全本地化時，請只使用 Chat 並確認上述覆寫已生效。

## Claude Code

CLI / Agent 開發工具。Claude Code 走的是 **Anthropic Messages API** 格式，
AGI BAR 已內建 `/v1/messages` 轉譯層，**不需要外部代理**。

```bash
export ANTHROPIC_BASE_URL="http://192.168.1.100:8787"
export ANTHROPIC_AUTH_TOKEN="agi-bar-你的Key"
export ANTHROPIC_MODEL="agi-bar-default"
```

Windows PowerShell：

```powershell
$env:ANTHROPIC_BASE_URL = "http://192.168.1.100:8787"
$env:ANTHROPIC_AUTH_TOKEN = "agi-bar-你的Key"
$env:ANTHROPIC_MODEL = "agi-bar-default"
```

> ⚠ **`ANTHROPIC_BASE_URL` 不要加 `/v1`。**
> Anthropic SDK 會自己補上 `/v1/messages`；若 Base URL 已含 `/v1`，
> 實際會打到 `/v1/v1/messages`。AGI BAR 兩種路徑都收，但正確寫法是不加。

先用 curl 確認：

```bash
curl http://192.168.1.100:8787/v1/messages \
  -H "x-api-key: agi-bar-你的Key" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"agi-bar-default","max_tokens":256,"messages":[{"role":"user","content":"你好"}]}'
```

回應應是標準的 Anthropic message 物件：

```json
{
  "id": "msg_...", "type": "message", "role": "assistant",
  "content": [{ "type": "text", "text": "..." }],
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 11, "output_tokens": 7 }
}
```

### 已實作的轉譯

| Anthropic | ↔ | OpenAI |
|---|---|---|
| `system` 頂層參數 | ↔ | `role: "system"` 訊息 |
| content block 陣列 | ↔ | 字串或 part 陣列 |
| `image` block（base64 / url） | → | `image_url` part |
| `tool_use` block | ↔ | `tool_calls` |
| `tool_result` block | ↔ | `role: "tool"` 訊息 |
| `input_schema` | ↔ | `function.parameters` |
| `tool_choice: any` | → | `tool_choice: "required"` |
| `end_turn` / `max_tokens` / `tool_use` | ↔ | `stop` / `length` / `tool_calls` |
| `message_start` … `message_stop` 事件流 | ↔ | OpenAI SSE chunk |
| `{"type":"error","error":{...}}` | ↔ | `{"error":{...}}` |

其他端點：

- `POST /v1/messages/count_tokens` — 回 `{ "input_tokens": N }`
- `GET /v1/models` — 帶 `anthropic-version` 標頭時回 Anthropic 格式的清單

### 限制

- Token 數為估算值（見「已知限制」）。上游有回報 `usage` 時以上游為準。
- 尚未支援 `anthropic-beta` 的實驗性功能、prompt caching 與 batch API。
- 實際可用的功能取決於後端本地模型：模型本身不支援工具呼叫時，
  Claude Code 的 Agent 功能會受限，這不是轉譯層的問題。

## Codex / OpenAI CLI 系工具

OpenAI 官方與相容 CLI 通常讀取這兩個環境變數：

```bash
export OPENAI_BASE_URL="http://192.168.1.100:8787/v1"
export OPENAI_API_KEY="agi-bar-你的Key"
```

部分版本使用 `OPENAI_API_BASE`（舊名）。

```toml
# ~/.codex/config.toml
model = "agi-bar-default"
model_provider = "agibar"

[model_providers.agibar]
name = "AGI BAR"
base_url = "http://192.168.1.100:8787/v1"
env_key = "OPENAI_API_KEY"

# 關鍵：新版 Codex 預設走 OpenAI Responses API（POST /v1/responses），
# AGI BAR 只提供 /v1/chat/completions。少了這行會連不上，
# 而且錯誤訊息通常不會直接指出原因。
wire_api = "chat"
```

> ⚠ **`wire_api = "chat"` 是 Codex 串接最容易卡住的一點。**
> 用 `node tests/integration/client-compat.mjs --client codex --emit ./out`
> 可以直接產生上面這份設定檔。

各家 CLI 的欄位名稱差異大，請以該工具當下版本的文件為準。

### 單次 Token 上限

Codex 與 Cursor 會把整份檔案塞進 prompt，動輒上萬 token。
若該人員的「單次最大 Token」設得太小，會出現**小型測試都過、實際使用卻大量
`413 request_too_large`** 的狀況。

設定檔預設值為 32768，與範例主力模型的 `contextWindow` 對齊。
換模型時記得一起檢查兩邊。

## DeepSeek（外部雲端備援）

DeepSeek 在 AGI BAR 中的定位是**管理員可選的備援路由**，不是預設模型。

啟用步驟：

**1. 設定金鑰環境變數**（**不要**寫進 `config.json`）

```powershell
setx DEEPSEEK_API_KEY "sk-你的DeepSeek金鑰"
```

`setx` 寫入的是使用者環境變數，**只對之後新開的行程生效**。
設定完必須**完全關閉 AGI BAR 再重新啟動**（不是重新整理網頁）。

確認有讀到：

```powershell
[Environment]::GetEnvironmentVariable("DEEPSEEK_API_KEY", "User") -ne $null
```

**2. 在管理台啟用**

「AI 模型」頁把 `cloud-deepseek` 按 **啟用**，再按 **立即健康檢查**。

- 狀態變 **線上** → 完成
- 仍顯示 `缺少環境變數 DEEPSEEK_API_KEY` → 服務還沒讀到新的環境變數，重啟服務
- 顯示 `HTTP 401` → 金鑰本身無效或已失效

**3. 決定它在路由中的位置**

新增的外部模型**預設不會進預設路由** —— 要不要用雲端備援是管理員的明確決定。

- 想讓全體人員在本地模型全掛時才用它：「AI 模型」頁的**預設模型順序**把它拖到最後一順位
- 只給特定人員：「人員 → 管理」裡設定該人員的專屬順序，把它放在末位

> ⚠ 啟用外部模型等同同意將該路由的 Prompt 送出本機網路。
> 設計原則是「本地開源模型優先」，未經授權不得把內部 Prompt 或程式碼送往外部。
> AGI BAR 對標記 `requiresExplicitConsent` 的模型會在未啟用時直接拒絕請求。

## 自製 App（iOS / Android / Windows / Web）

任何 HTTP 客戶端都能直接呼叫：

```js
const res = await fetch('http://192.168.1.100:8787/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer agi-bar-你的Key',
  },
  body: JSON.stringify({
    model: 'agi-bar-default',
    messages: [{ role: 'user', content: '你好' }],
    stream: true,
  }),
});
```

Web App 從瀏覽器直接呼叫時會遇到 CORS。請把該網頁的來源加入
`config/config.json` 的 `security.allowedOrigins`：

```json
{ "security": { "allowedOrigins": ["http://192.168.1.50:3000"] } }
```

> 行動 App 請勿把 API Key 硬編在前端。建議由自家後端代為呼叫，
> 或為每位使用者配發個別 Key 並提供撤銷機制。

## 其他 OpenAI 相容客戶端

只要能自訂 Base URL 與 API Key 即可，例如 Open WebUI、LibreChat、Chatbox、
Continue.dev、LangChain 的 `ChatOpenAI`、LlamaIndex 的 `OpenAILike`。

AGI BAR 目前實作的端點：

| 端點 | 格式 | 說明 |
|---|---|---|
| `GET /v1/models` | OpenAI / Anthropic | 模型清單（依 `anthropic-version` 標頭切換格式） |
| `GET /v1/models/:id` | OpenAI | 單一模型 |
| `POST /v1/chat/completions` | OpenAI | 對話，支援 `stream: true` |
| `POST /v1/completions` | OpenAI | 舊版文字補全（內部轉為 chat） |
| `POST /v1/messages` | Anthropic | 對話，支援 `stream: true` |
| `POST /v1/messages/count_tokens` | Anthropic | 估算輸入 Token |
| `GET /v1/me` | AGI BAR | 查詢自身額度與用量 |

兩種格式共用同一條管線與同一份配額 —— 不論走 `/v1/chat/completions` 還是
`/v1/messages`，驗證、時段、Token 額度、佇列優先權與紀錄都是同一套。

尚未實作：`/v1/embeddings`、`/v1/images`、`/v1/audio`。
用到這些功能的客戶端會收到 `404 unknown_endpoint`。

## 錯誤代碼對照

客戶端收到的錯誤都是 OpenAI 格式，`error.code` 可據以判斷原因：

| code | HTTP | 意義 |
|---|---|---|
| `missing_api_key` | 401 | 沒帶 Authorization |
| `invalid_api_key` | 401 | Key 不存在或已刪除 |
| `key_inactive` | 403 | Key 被暫停或撤銷 |
| `user_inactive` | 403 | 人員帳號被停用 |
| `expired` / `not_yet_valid` | 403 | 超出有效日期 |
| `outside_time_window` | 403 | 不在允許時段 |
| `weekday_not_allowed` | 403 | 今天不在允許星期 |
| `rate_limit_exceeded` | 429 | 超過 RPM |
| `concurrency_limit` | 429 | 超過同時請求數 |
| `quota_exceeded` | 429 | Token 配額用盡（Hard 政策） |
| `request_too_large` | 413 | 單次請求超過上限 |
| `queue_full` / `queue_timeout` | 503 / 504 | 佇列滿載或等待逾時 |
| `all_models_unavailable` | 503 | 路由中的模型全數不可用 |
