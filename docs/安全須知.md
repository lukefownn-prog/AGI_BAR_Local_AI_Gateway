## 絕對不可上傳 GitHub 的資料

以下項目已全部列入 `.gitignore`。**提交前請再確認一次。**

| 類別 | 項目 |
|---|---|
| 憑證 | API Key、管理員密碼、Session Secret、`.env`、`*.pem`、`*.key`、`*.pfx` |
| 設定 | 真實的 `config/config.json`（只保留 `config.example.json`） |
| 資料 | `data/`、`*.db`、`users.db`、`usage.db`、request logs、員工資料 |
| 模型 | `models/`、`*.gguf`、`*.safetensors`、模型授權憑證 |
| 內網 | 內網 IP 清單、NAS/路由器位址、`lan-hosts.txt` |
| 備份 | `backups/`、`exports/`、`*.bak` |

檢查是否誤加：

```bash
git status --porcelain
git check-ignore -v config/config.json data/agibar.db
```

若機密**已經**被提交過，改 `.gitignore` 是不夠的 —— 歷史仍在。
必須輪換該憑證（換發 API Key、改管理員密碼、重新產生 `data/session.secret`），
必要時用 `git filter-repo` 重寫歷史。

## 管理介面的存取隔離

**預設只有 AI 主機本機能開管理台。** 區網人員只看得到 `/v1` 與網頁聊天。

| 路徑 | 本機 | 區網 |
|---|---|---|
| `/`（登入頁） | ✓ | 302 導向 `/chat.html` |
| `/app.html`（管理台） | ✓ | **404** |
| `/api/*`（管理 API） | ✓ | **404** |
| `/assets/app.js`、`login.js` | ✓ | **404** |
| `/chat.html`（網頁聊天） | ✓ | ✓ |
| `/v1/*`（API） | ✓ | ✓ |
| `/api/health`（監控用） | ✓ | ✓ |

### 為什麼是 404 而不是 403

403 等於告訴對方「這裡有東西，只是你不能進」，反而指出了值得攻擊的目標。
404 讓管理台從區網看起來根本不存在。

### 這不是「換一個猜不到的網址」

把管理台搬到隨機路徑只要有人看過一次網址、或翻到瀏覽紀錄就破功。
這裡用的是**來源位址判定**：

- 依據是 TCP 連線的對端位址（`req.socket.remoteAddress`）。
  這個值無法偽造 —— 要讓三向交握完成，封包必須真的回得到那個位址。
- **絕不使用 `X-Forwarded-For`。** 那是請求標頭，任何人都能自己填；
  拿它做存取控制等於沒有控制。即使 `server.trustProxy` 開著也一樣，
  那個設定只影響「紀錄裡寫哪個 IP」，不影響授權判定。

### 設定

```json
{
  "security": {
    "adminAccess": "loopback",
    "adminAllowedCidrs": []
  }
}
```

- `loopback`（預設）— 只有 AI 主機本機
- `lan` — 同網段皆可存取（**只在你確定需要時才改**）
- `adminAllowedCidrs` — 額外放行特定來源，例如管理員自己的電腦
  `["192.168.1.50/32"]`

### 副作用

壓測與串接驗證腳本需要管理 API 來建立測試人員，因此**必須在 AI 主機上執行**，
或把執行機器的 IP 加進 `adminAllowedCidrs`。
串接探針也可以改用 `--key` 直接指定既有 API Key，那條路徑不需要管理權限。

### 若要透過反向代理對外開放

代理會讓所有請求的來源位址變成代理自己（通常是回送位址），
**管理台就等於對所有人開放了**。這種部署必須在代理層自行擋掉
`/app.html`、`/api/`（`/api/health` 除外），不能只靠這裡的設定。

## 已知限制

以下是 V1 明確**不涵蓋**的範圍，部署時請自行補足：

- **無 TLS。** 服務走 HTTP。API Key 在 LAN 上以明文傳輸。
  對外開放或跨不信任網段時，請置於 Nginx / Caddy 反向代理後啟用 HTTPS，
  並把 `security.forceHttpsCookies` 設為 `true`。
- **無 Web Chat 的獨立認證。** 網頁聊天是把 API Key 存在瀏覽器 localStorage。
  共用電腦上請提醒人員用完清除。
- **管理台無雙因素認證。** V1 僅有密碼 + 登入速率限制。
- **Token 估算非精確 tokenizer。** 上游有回報 `usage` 時以上游為準；
  沒有時用啟發式估算（中日韓字元約 1 token，其餘約 4 字元 1 token）。
  配額判定因此可能有誤差，Hard Limit 請預留餘裕。
- **併發與 RPM 計數存在記憶體中。** 服務重啟後歸零；Token 配額則落在資料庫，不受影響。
- **無防暴力破解封鎖。** 只有每 IP 每分鐘的登入次數限制，沒有帳號鎖定。

## 部署前檢查清單

- [ ] 已修改初始管理員密碼（不是 `agibar-admin`）
- [ ] `config/config.json` 未被 git 追蹤（`git check-ignore` 確認）
- [ ] `data/session.secret` 已自動產生且未進版本庫
- [ ] 外部雲端模型（DeepSeek 等）確認是否該啟用；預設停用
- [ ] 外部模型憑證放在環境變數，不在 `config.json` 裡
- [ ] `server.host` 依需求設定（`0.0.0.0` 開放 LAN / `127.0.0.1` 僅本機）
- [ ] 防火牆規則已核准，Port 與程式路徑已報備 EDR
- [ ] `logging.logPrompts` 為 `false`（預設只記錄雜湊）
- [ ] `logging.retentionDays` 依留存政策設定（同時涵蓋日誌檔與資料庫紀錄；設 0 為永久保留）
- [ ] 備份已啟用且 `data/backups/` 有檔案產生
- [ ] 已對每位人員設定合理的 Token 配額與時段
- [ ] `security.adminAccess` 為 `loopback`（除非確定需要開放）
- [ ] 已從區網另一台機器實測 `/app.html` 回 404
- [ ] 已跑過 `npm test`，169 項全過
- [ ] 已跑過壓力測試（見 [tests/load/README.md](../tests/load/README.md)），驗收判定全數通過

## 回報安全問題

發現安全問題請開 Issue 並加上 `security` 標籤。若問題尚未修復且可被利用，
請改用 GitHub 的 **Private vulnerability reporting**（Security 分頁）私下回報，
待修復後再公開。

無論哪種方式，**都不要**在內容中貼出實際的 API Key、密碼或內網位址 ——
重現步驟請以佔位符代替。
