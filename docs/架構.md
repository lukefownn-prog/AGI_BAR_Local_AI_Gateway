# 系統架構

> 對應規畫書第 2、7、8、12 節。

## 請求管線

```
使用者 / AI 開發工具 / App
        │  Authorization: Bearer agi-bar-xxxxxxxx
        ▼
┌────────────────────────────────────────────────────┐
│ AGI BAR Web Gateway  (server/index.mjs)            │
├────────────────────────────────────────────────────┤
│ 1. API 驗證      authenticateApiKey()  SHA-256 比對 │
│ 2. 時間權限      checkTimeWindow()     日期/星期/時段│
│ 3. Token Quota   preflight()           4 層配額     │
│ 4. 併發控制      acquireSlot()         per-key      │
│ 5. Priority Queue queue.acquire()      P0-P3 + 反飢餓│
│ 6. Model Router  callWithFailover()    順位 1→2→3→4 │
└────────────────────────────────────────────────────┘
        ▼
本地模型池：local-primary → local-secondary → local-small
        ▼（必要時，且該 Key 已授權）
受控 Web Search / URL Fetch → Internet
```

任一關卡失敗都會以 OpenAI 錯誤格式回傳，客戶端能顯示可讀訊息。
無論成功或失敗，`finally` 區塊一定會釋放佇列名額與併發計數，並寫入
`usage_logs` 與 `request_logs`。

## 模組職責

| 檔案 | 職責 |
|---|---|
| `core/paths.mjs` | 所有路徑的唯一來源，支援 `AGIBAR_DATA_DIR` 隔離 |
| `core/config.mjs` | 設定載入與合併，外部憑證只從環境變數讀取 |
| `core/db.mjs` | SQLite 存取（`node:sqlite`）、交易、稽核 |
| `core/crypto.mjs` | scrypt 密碼、API Key 產生與雜湊、HMAC 簽章 |
| `core/http.mjs` | 迷你路由、JSON 解析、Cookie、SSE |
| `services/users.mjs` | 人員 CRUD、初始管理員 |
| `services/apikeys.mjs` | Key 生命週期、限制欄位、Bearer 驗證 |
| `services/quota.mjs` | 時間權限、四層配額、RPM、併發、Token 估算 |
| `services/models.mjs` | 模型註冊、Health Check、統計 |
| `services/routes.mjs` | 每人的 Model Routing Chain |
| `services/queue.mjs` | Priority Queue + anti-starvation |
| `services/gateway.mjs` | 串起整條管線、Failover、紀錄 |
| `services/websafe.mjs` | SSRF 防護、受控 Fetch / Search |
| `services/backup.mjs` | 一致性備份與保留策略 |

## Failover 判定

`isUsable()` 認定模型不可用的條件（規畫書 7）：

- `enabled = 0` — 管理員停用
- `health_state = 'offline'` 且連續失敗次數 ≥ `unhealthyAfterFailures`
- `queue_depth ≥ queueTooLongThreshold` — Queue 過長

呼叫上游時額外處理：

- HTTP 5xx、連線失敗、逾時 → 換下一順位
- HTTP 429 / 408 / 409 / 425 → 換下一順位（可能只是這台忙）
- 其他 4xx → **不換**，直接回報。請求本身有問題，換模型也不會好

## Anti-starvation

有效權重 = 基礎權重 − min(maxBoost, ⌊等待時間 / boostEveryMs⌋)，數字越小越先執行。

預設 `boostEveryMs = 10000`、`maxBoost = 3`，代表一個 P3 訪客請求等待 30 秒後
有效權重降到 0，與 P0 管理員同級。同權重時先進先出。

## 資料表

| 資料表 | 用途 |
|---|---|
| `users` | 人員與角色 |
| `api_keys` | Key 識別、雜湊、狀態 |
| `api_key_limits` | Token / 時間 / RPM / Concurrent 限制 |
| `models` | 模型、Endpoint、狀態、能力、健康觀測值 |
| `model_routes` | 每位人員的模型優先順序 |
| `usage_logs` | Input/Output/Total Token 與模型使用量 |
| `request_logs` | 時間、等待、推理、錯誤、Web 使用 |
| `web_access_logs` | 受控上網的目標、解析 IP、放行/封鎖 |
| `audit_logs` | 管理操作稽核 |
| `admin_sessions` | 管理員 Session |
| `system_settings` | 全域設定與安全政策 |

V1 使用 SQLite（WAL 模式）。未來多人管理或多節點時再升級 PostgreSQL —— 
所有查詢都寫成標準 SQL，遷移時主要調整的是 `datetime('now')` 與 `strftime` 這類函式。

## 為什麼零相依

Portable ZIP 的目標是「解壓即用」。任何 npm 相依都會帶來三個問題：
需要 `npm install`、可能有原生模組編譯、供應鏈風險。

Node 22.5 起內建的 `node:sqlite` 讓資料庫不再需要 `better-sqlite3`；
`node:http` 與 `node:crypto` 足以支撐這個規模的 Gateway。
代價是自己寫了迷你路由與 SSE 處理，約 200 行，換來零安裝與零供應鏈風險。
