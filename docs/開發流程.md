# 開發與版本管理流程

> 對應規畫書第 15、16、17 節。

## Repository 設定

**本 Repository 為 Private（不公開）。**

程式碼、Issue、版本、Release 與文件由 GitHub 管理；
模型檔、API Key、使用紀錄、資料庫與公司內部設定**不得**上傳（見 [安全須知.md](安全須知.md)）。

## 開發流程

```
需求確認 → 建立 GitHub Issue → 建立功能分支
   → Codex / Claude Code / Cursor 開發 → 本機測試
   → Commit → Push → Pull Request → Code Review → 自動測試
   → Merge main → 建立版本 Tag → GitHub Release
   → 產生 Portable ZIP → 部署 AGI BAR
```

## Branch 規則

| Branch | 用途 |
|---|---|
| `main` | 穩定、可發布版本 |
| `develop` | 整合下一版本功能（可選） |
| `feature/xxx` | 新功能，例如 `feature/api-key-quota` |
| `fix/xxx` | Bug 修正 |
| `docs/xxx` | 文件與規格更新 |

```bash
git switch -c feature/embeddings-endpoint
# …開發…
npm test
git commit -m "feat(api): 新增 /v1/embeddings 端點

Closes #12"
git push -u origin feature/embeddings-endpoint
gh pr create --fill
```

## Commit 訊息

採 Conventional Commits：

```
feat(scope): 新功能
fix(scope): 修正
docs(scope): 文件
test(scope): 測試
refactor(scope): 重構
chore(scope): 雜項
```

常用 scope：`api`、`admin`、`queue`、`router`、`quota`、`ui`、`scripts`。

## AI 開發工具與 GitHub（規畫書 15.4）

Codex、Claude Code、Cursor 都以**同一個 Git Repository** 為工作基礎。

**規則：**

1. AI 修改程式前先讀取 Issue 與目前 Branch
2. **只修改該 Issue 範圍內的檔案**
3. 完成後執行 `npm test`，全過才提交
4. **避免多個 AI 同時直接修改 `main`** —— 一律走 feature branch + PR

**建議分工：**

| 工具 | 定位 |
|---|---|
| Codex | 實作、修正、測試、Git 操作 |
| Claude Code | 大型功能、架構重構、Code Review |
| Cursor | 人工互動式修改與快速檢查 |
| DeepSeek | 本地/外部程式模型或第二意見，仍走相同 Git 流程 |

## CI（規畫書 16.2）

每個 Pull Request 自動執行：

1. **程式語法檢查** — `node --check` 掃過所有 `.mjs`
2. **單元測試** — 佇列、配額、SSRF 防護
3. **API 測試** — 端對端管線（含 mock 模型的 Failover）
4. **安全掃描** — 掃描是否有機密誤入版本庫、`.gitignore` 涵蓋度檢查
5. **Portable 結構檢查** — 確認必要檔案齊全、無 npm 相依

`main` 通過後才允許建立 Release。**正式部署所需的敏感設定不放入 Actions Artifact。**

## Release 流程（規畫書 16.3）

```bash
# 1. 確認 main 穩定
git switch main && git pull && npm test

# 2. 更新 CHANGELOG.md 與 package.json 版本號

# 3. 打 Tag
git tag -a v1.2.1 -m "v1.2.1"
git push origin v1.2.1

# 4. 建置 Portable ZIP（會一併算 SHA-256）
npm run build:portable

# 5. 建立 Release 並上傳
gh release create v1.2.1 \
  dist/AGI-BAR-v1.2.1-win64.zip \
  dist/AGI-BAR-v1.2.1-win64.zip.sha256 \
  --title "v1.2.1" --notes-file docs/release-notes/v1.2.1.md
```

管理員下載 ZIP → 核對 SHA-256 → 解壓 → **保留既有 `data/` 與 `config/`** → 啟動 → 健康檢查。

## Portable ZIP 與 GitHub 的關係（規畫書 16.4）

- **GitHub Repository** 保存「程式碼」
- **GitHub Release** 提供「可部署 ZIP」
- **大型 GGUF 模型不進 Git Repository**，由管理員在首次部署後放入 `models/`

## 版本號

採 Semantic Versioning：

- **MAJOR** — 不相容的 API 或資料庫結構變更（需要遷移腳本）
- **MINOR** — 向下相容的新功能
- **PATCH** — 向下相容的修正

資料庫結構有變更時，必須在 `CHANGELOG.md` 明確標示，並在
`docs/部署.md` 補上該版本的遷移步驟。
