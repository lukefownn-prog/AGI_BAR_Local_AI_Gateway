# Connecting external tools and AI clients

[繁體中文](整合設定.md) ｜ **English** ｜ [日本語](整合設定.ja.md)

> Corresponds to section 10 of the design document.

Every client shares the same three pieces of information:

| Item | Value |
|---|---|
| Base URL | `http://<AI-host-IP>:8787/v1` |
| API key | Each person's own `agi-bar-xxxxxxxx` |
| Model name | `agi-bar-default` (or `agi-bar-fast` / `agi-bar-long`) |

**The model name is an alias, not the real backend model.** The gateway picks a backend according
to the model routing chain the administrator configured for that person; users neither need nor
see the actual model name.

**Run the automated check before configuring anything by hand.** The script sends the requests
each client actually makes, so it finds the sticking points before you spend time on setup, and
prints configuration you can paste directly:

```bash
node tests/integration/client-compat.mjs --url http://192.168.1.100:8787 --key agi-bar-YOUR-KEY
```

See [tests/integration/README.en.md](../tests/integration/README.en.md).

Or confirm the key works by hand:

```bash
curl http://192.168.1.100:8787/v1/models -H "Authorization: Bearer agi-bar-YOUR-KEY"
```

## Cursor

A development IDE, using local models through the AGI BAR API.

1. `Settings` → `Models` → `OpenAI API Key`
2. Tick **Override OpenAI Base URL** and enter `http://<AI-host-IP>:8787/v1`
3. Put `agi-bar-xxxxxxxx` in the API key field
4. Add `agi-bar-default` to the custom model list and disable the other cloud models
5. Press **Verify** to confirm the connection

> Some Cursor features (tab completion, certain Composer modes) go to Cursor's own servers and do
> not pass through AGI BAR. If you need everything to stay local, use Chat only and confirm the
> override above is in effect.

## Claude Code

A CLI / agent development tool. Claude Code speaks the **Anthropic Messages API** format; AGI BAR
has a built-in `/v1/messages` translation layer, so **no external proxy is needed**.

```bash
export ANTHROPIC_BASE_URL="http://192.168.1.100:8787"
export ANTHROPIC_AUTH_TOKEN="agi-bar-YOUR-KEY"
export ANTHROPIC_MODEL="agi-bar-default"
```

Windows PowerShell:

```powershell
$env:ANTHROPIC_BASE_URL = "http://192.168.1.100:8787"
$env:ANTHROPIC_AUTH_TOKEN = "agi-bar-YOUR-KEY"
$env:ANTHROPIC_MODEL = "agi-bar-default"
```

> ⚠ **Do not append `/v1` to `ANTHROPIC_BASE_URL`.**
> The Anthropic SDK adds `/v1/messages` itself; if the base URL already contains `/v1`, requests
> land on `/v1/v1/messages`. AGI BAR accepts both paths, but the correct form omits it.

Confirm with curl first:

```bash
curl http://192.168.1.100:8787/v1/messages \
  -H "x-api-key: agi-bar-YOUR-KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"agi-bar-default","max_tokens":256,"messages":[{"role":"user","content":"Hello"}]}'
```

The response should be a standard Anthropic message object:

```json
{
  "id": "msg_...", "type": "message", "role": "assistant",
  "content": [{ "type": "text", "text": "..." }],
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 11, "output_tokens": 7 }
}
```

### Translation coverage

| Anthropic | ↔ | OpenAI |
|---|---|---|
| Top-level `system` parameter | ↔ | `role: "system"` message |
| Content block array | ↔ | String or part array |
| `image` block (base64 / url) | → | `image_url` part |
| `tool_use` block | ↔ | `tool_calls` |
| `tool_result` block | ↔ | `role: "tool"` message |
| `input_schema` | ↔ | `function.parameters` |
| `tool_choice: any` | → | `tool_choice: "required"` |
| `end_turn` / `max_tokens` / `tool_use` | ↔ | `stop` / `length` / `tool_calls` |
| `message_start` … `message_stop` event stream | ↔ | OpenAI SSE chunks |
| `{"type":"error","error":{...}}` | ↔ | `{"error":{...}}` |

Other endpoints:

- `POST /v1/messages/count_tokens` — returns `{ "input_tokens": N }`
- `GET /v1/models` — returns an Anthropic-format list when the `anthropic-version` header is present

### Limitations

- Token counts are estimates (see "Known limitations"). When upstream reports `usage`, that value
  wins.
- Experimental `anthropic-beta` features, prompt caching and the batch API are not supported yet.
- What actually works depends on the backend local model: if the model itself does not support
  tool calling, Claude Code's agent features are limited. That is not a translation-layer problem.

## Codex / OpenAI-style CLI tools

Official and compatible OpenAI CLIs usually read these two environment variables:

```bash
export OPENAI_BASE_URL="http://192.168.1.100:8787/v1"
export OPENAI_API_KEY="agi-bar-YOUR-KEY"
```

Some versions use the older name `OPENAI_API_BASE`.

```toml
# ~/.codex/config.toml
model = "agi-bar-default"
model_provider = "agibar"

[model_providers.agibar]
name = "AGI BAR"
base_url = "http://192.168.1.100:8787/v1"
env_key = "OPENAI_API_KEY"

# The key line: newer Codex versions default to the OpenAI Responses API
# (POST /v1/responses), while AGI BAR only offers /v1/chat/completions.
# Without this line it cannot connect, and the error message usually does
# not say why.
wire_api = "chat"
```

> ⚠ **`wire_api = "chat"` is the single most common sticking point with Codex.**
> `node tests/integration/client-compat.mjs --client codex --emit ./out` generates the file above
> for you.

Field names differ considerably between CLIs — follow the documentation for the version you have.

### Per-request token limit

Codex and Cursor push entire files into the prompt, easily tens of thousands of tokens. If that
person's "max tokens per request" is set too low, you get **small tests passing while real usage
throws `413 request_too_large` constantly**.

The config default is 32768, aligned with the example primary model's `contextWindow`. Remember to
check both sides when you change models.

## DeepSeek (external cloud fallback)

Within AGI BAR, DeepSeek is positioned as an **optional fallback route the administrator chooses**,
not a default model.

To enable it:

**1. Set the key environment variable** (**do not** write it into `config.json`)

```powershell
setx DEEPSEEK_API_KEY "sk-your-deepseek-key"
```

`setx` writes a user environment variable that **only affects processes started afterwards**.
After setting it you must **shut AGI BAR down completely and start it again** — refreshing the
page is not enough.

Confirm it was picked up:

```powershell
[Environment]::GetEnvironmentVariable("DEEPSEEK_API_KEY", "User") -ne $null
```

**2. Enable it in the admin console**

On the AI Models page, press **Enable** on `cloud-deepseek`, then **Run health check**.

- Status becomes **Online** → done
- Still showing `missing environment variable DEEPSEEK_API_KEY` → the service has not picked up
  the new variable; restart it
- Showing `HTTP 401` → the key itself is invalid or expired

**3. Decide its position in the route**

A newly added external model **stays out of the default route by default** — whether to use a
cloud fallback is the administrator's explicit decision.

- To let everyone fall back to it only when all local models are down: drag it to the last rank
  under **Default model order** on the AI Models page
- For specific people only: set that person's own order under Users → Manage, with it last

> ⚠ Enabling an external model means agreeing that prompts on that route leave your local network.
> The design principle is "local open-source models first"; internal prompts or code must not be
> sent externally without authorisation. AGI BAR rejects requests outright for models marked
> `requiresExplicitConsent` while they are not enabled.

## Your own apps (iOS / Android / Windows / Web)

Any HTTP client can call it directly:

```js
const res = await fetch('http://192.168.1.100:8787/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer agi-bar-YOUR-KEY',
  },
  body: JSON.stringify({
    model: 'agi-bar-default',
    messages: [{ role: 'user', content: 'Hello' }],
    stream: true,
  }),
});
```

A web app calling directly from the browser will hit CORS. Add that page's origin to
`security.allowedOrigins` in `config/config.json`:

```json
{ "security": { "allowedOrigins": ["http://192.168.1.50:3000"] } }
```

> Do not hard-code API keys into a mobile app's front end. Have your own backend make the call, or
> issue an individual key per user with a revocation path.

## Other OpenAI-compatible clients

Anything that lets you set a base URL and API key will work — Open WebUI, LibreChat, Chatbox,
Continue.dev, LangChain's `ChatOpenAI`, LlamaIndex's `OpenAILike`, and so on.

Endpoints AGI BAR currently implements:

| Endpoint | Format | Notes |
|---|---|---|
| `GET /v1/models` | OpenAI / Anthropic | Model list (format switches on the `anthropic-version` header) |
| `GET /v1/models/:id` | OpenAI | A single model |
| `POST /v1/chat/completions` | OpenAI | Chat, supports `stream: true` |
| `POST /v1/completions` | OpenAI | Legacy text completion (converted to chat internally) |
| `POST /v1/messages` | Anthropic | Chat, supports `stream: true` |
| `POST /v1/messages/count_tokens` | Anthropic | Estimates input tokens |
| `GET /v1/me` | AGI BAR | Query your own quota and usage |

Both formats share one pipeline and one quota — whether you go through `/v1/chat/completions` or
`/v1/messages`, authentication, time windows, token limits, queue priority and logging are
identical.

Not implemented yet: `/v1/embeddings`, `/v1/images`, `/v1/audio`. Clients that use these receive
`404 unknown_endpoint`.

## Error code reference

Errors reach clients in the OpenAI format; `error.code` tells you the cause:

| code | HTTP | Meaning |
|---|---|---|
| `missing_api_key` | 401 | No Authorization header |
| `invalid_api_key` | 401 | The key does not exist or was deleted |
| `key_inactive` | 403 | The key is paused or revoked |
| `user_inactive` | 403 | The user account is disabled |
| `expired` / `not_yet_valid` | 403 | Outside the valid date range |
| `outside_time_window` | 403 | Outside the allowed time window |
| `weekday_not_allowed` | 403 | Today is not an allowed weekday |
| `rate_limit_exceeded` | 429 | RPM exceeded |
| `concurrency_limit` | 429 | Too many simultaneous requests |
| `quota_exceeded` | 429 | Token quota exhausted (hard policy) |
| `request_too_large` | 413 | A single request exceeds the limit |
| `queue_full` / `queue_timeout` | 503 / 504 | Queue saturated, or waited too long |
| `all_models_unavailable` | 503 | Every model in the route is unavailable |
