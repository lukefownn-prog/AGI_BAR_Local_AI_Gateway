# 外部ツール / AI クライアントの接続設定

[繁體中文](整合設定.md) ｜ [English](整合設定.en.md) ｜ **日本語**

> 企画書の第 10 節に対応します。

すべてのクライアントは同じ 3 つの情報を共有します。

| 項目 | 値 |
|---|---|
| Base URL | `http://<AI ホストの IP>:8787/v1` |
| API キー | 利用者ごとの `agi-bar-xxxxxxxx` |
| モデル名 | `agi-bar-default`（または `agi-bar-fast` / `agi-bar-long`） |

**モデル名はエイリアスであり、バックエンドの実際のモデルではありません。** ゲートウェイは
管理者がその利用者に設定したモデルルーティングチェーンに従ってバックエンドを選択します。
利用者は実際のモデル名を知る必要も、見ることもありません。

**手作業で設定する前に、まず自動検証を実行してください。** スクリプトが各クライアントの
実際に送るリクエストを一通り投げるため、設定に時間を使う前に詰まる箇所が判明し、
そのまま貼り付けられる設定も出力されます。

```bash
node tests/integration/client-compat.mjs --url http://192.168.1.100:8787 --key agi-bar-あなたのキー
```

詳細は [tests/integration/README.md](../tests/integration/README.md) を参照。

手動でキーの動作を確認する場合：

```bash
curl http://192.168.1.100:8787/v1/models -H "Authorization: Bearer agi-bar-あなたのキー"
```

## Cursor

開発 IDE。AGI BAR API 経由でローカルモデルを使用します。

1. `Settings` → `Models` → `OpenAI API Key`
2. **Override OpenAI Base URL** にチェックを入れ、`http://<AI ホストの IP>:8787/v1` を入力
3. API Key 欄に `agi-bar-xxxxxxxx` を入力
4. カスタムモデル一覧に `agi-bar-default` を追加し、他のクラウドモデルを無効化
5. **Verify** を押して接続を確認

> Cursor の一部機能（タブ補完、Composer の一部モード）は Cursor 自社サーバーを経由し、
> AGI BAR を通りません。完全にローカルで完結させたい場合は Chat のみを使い、
> 上記のオーバーライドが有効になっていることを確認してください。

## Claude Code

CLI / エージェント開発ツール。Claude Code は **Anthropic Messages API** 形式を使いますが、
AGI BAR には `/v1/messages` の変換層が組み込まれているため、**外部プロキシは不要**です。

```bash
export ANTHROPIC_BASE_URL="http://192.168.1.100:8787"
export ANTHROPIC_AUTH_TOKEN="agi-bar-あなたのキー"
export ANTHROPIC_MODEL="agi-bar-default"
```

Windows PowerShell：

```powershell
$env:ANTHROPIC_BASE_URL = "http://192.168.1.100:8787"
$env:ANTHROPIC_AUTH_TOKEN = "agi-bar-あなたのキー"
$env:ANTHROPIC_MODEL = "agi-bar-default"
```

> ⚠ **`ANTHROPIC_BASE_URL` に `/v1` を付けないでください。**
> Anthropic SDK が自動で `/v1/messages` を補います。Base URL に既に `/v1` が含まれていると
> 実際には `/v1/v1/messages` へ飛びます。AGI BAR は両方のパスを受けますが、
> 正しい書き方は付けないことです。

まず curl で確認：

```bash
curl http://192.168.1.100:8787/v1/messages \
  -H "x-api-key: agi-bar-あなたのキー" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"agi-bar-default","max_tokens":256,"messages":[{"role":"user","content":"こんにちは"}]}'
```

応答は標準的な Anthropic の message オブジェクトになるはずです：

```json
{
  "id": "msg_...", "type": "message", "role": "assistant",
  "content": [{ "type": "text", "text": "..." }],
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 11, "output_tokens": 7 }
}
```

### 実装済みの変換

| Anthropic | ↔ | OpenAI |
|---|---|---|
| トップレベルの `system` パラメーター | ↔ | `role: "system"` メッセージ |
| content block の配列 | ↔ | 文字列または part 配列 |
| `image` block（base64 / url） | → | `image_url` part |
| `tool_use` block | ↔ | `tool_calls` |
| `tool_result` block | ↔ | `role: "tool"` メッセージ |
| `input_schema` | ↔ | `function.parameters` |
| `tool_choice: any` | → | `tool_choice: "required"` |
| `end_turn` / `max_tokens` / `tool_use` | ↔ | `stop` / `length` / `tool_calls` |
| `message_start` … `message_stop` のイベント列 | ↔ | OpenAI SSE チャンク |
| `{"type":"error","error":{...}}` | ↔ | `{"error":{...}}` |

その他のエンドポイント：

- `POST /v1/messages/count_tokens` —— `{ "input_tokens": N }` を返す
- `GET /v1/models` —— `anthropic-version` ヘッダー付きなら Anthropic 形式の一覧を返す

### 制限

- トークン数は推定値です（「既知の制限」参照）。上流が `usage` を返す場合はそちらを優先します。
- `anthropic-beta` の実験的機能、プロンプトキャッシュ、バッチ API は未対応です。
- 実際に使える機能はバックエンドのローカルモデル次第です。モデル自体がツール呼び出しに
  対応していない場合、Claude Code のエージェント機能は制限されます。これは変換層の問題では
  ありません。

## Codex / OpenAI 系 CLI ツール

OpenAI 公式および互換 CLI は通常この 2 つの環境変数を読みます：

```bash
export OPENAI_BASE_URL="http://192.168.1.100:8787/v1"
export OPENAI_API_KEY="agi-bar-あなたのキー"
```

バージョンによっては旧名の `OPENAI_API_BASE` を使います。

```toml
# ~/.codex/config.toml
model = "agi-bar-default"
model_provider = "agibar"

[model_providers.agibar]
name = "AGI BAR"
base_url = "http://192.168.1.100:8787/v1"
env_key = "OPENAI_API_KEY"

# 重要：新しい Codex は既定で OpenAI Responses API（POST /v1/responses）を使いますが、
# AGI BAR が提供するのは /v1/chat/completions だけです。この 1 行が無いと接続できず、
# しかもエラーメッセージは通常その理由を示してくれません。
wire_api = "chat"
```

> ⚠ **`wire_api = "chat"` は Codex 接続で最も詰まりやすいポイントです。**
> `node tests/integration/client-compat.mjs --client codex --emit ./out` を実行すると、
> 上記の設定ファイルをそのまま生成できます。

CLI ごとに項目名の差が大きいため、使用中のバージョンのドキュメントを優先してください。

### 1 回あたりのトークン上限

Codex や Cursor はファイル全体をプロンプトに詰め込むため、容易に数万トークンに達します。
その利用者の「1 回あたり最大トークン」が小さすぎると、**小さなテストは通るのに実運用では
`413 request_too_large` が多発する**という状況になります。

設定ファイルの既定値は 32768 で、サンプルのメインモデルの `contextWindow` に合わせてあります。
モデルを変えるときは両方を確認してください。

## DeepSeek（外部クラウドの予備）

AGI BAR における DeepSeek は、**管理者が選択できる予備ルート**という位置づけであり、
既定のモデルではありません。

有効化の手順：

**1. キーの環境変数を設定**（`config.json` には**書かない**）

```powershell
setx DEEPSEEK_API_KEY "sk-あなたの DeepSeek キー"
```

`setx` はユーザー環境変数に書き込み、**その後に起動したプロセスにのみ有効**です。
設定後は**AGI BAR を完全に終了してから再起動**してください（ページの再読み込みでは不十分）。

読み込まれたか確認：

```powershell
[Environment]::GetEnvironmentVariable("DEEPSEEK_API_KEY", "User") -ne $null
```

**2. 管理コンソールで有効化**

「AI モデル」ページで `cloud-deepseek` の **有効化** を押し、続いて **ヘルスチェック実行**。

- 状態が **オンライン** になれば完了
- `環境変数 DEEPSEEK_API_KEY がありません` のままなら、サービスが新しい環境変数を
  読み込んでいません。再起動してください
- `HTTP 401` なら、キー自体が無効か失効しています

**3. ルート内の位置を決める**

追加した外部モデルは**既定ではルートに入りません** —— クラウド予備を使うかどうかは
管理者の明示的な判断だからです。

- ローカルモデルが全滅したときだけ全員に使わせたい場合：「AI モデル」ページの
  **既定のモデル順序**で最後の順位に配置
- 特定の利用者だけに使わせる場合：「人員 → 管理」でその利用者専用の順序を設定し、最後に置く

> ⚠ 外部モデルの有効化は、そのルートのプロンプトがローカルネットワークの外へ送信されることへの
> 同意を意味します。設計原則は「ローカルのオープンソースモデル優先」であり、許可なく内部の
> プロンプトやコードを外部へ送ってはいけません。AGI BAR は `requiresExplicitConsent` が
> 付いたモデルについて、有効化されていない間はリクエストを直接拒否します。

## 自作アプリ（iOS / Android / Windows / Web）

任意の HTTP クライアントから直接呼び出せます：

```js
const res = await fetch('http://192.168.1.100:8787/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer agi-bar-あなたのキー',
  },
  body: JSON.stringify({
    model: 'agi-bar-default',
    messages: [{ role: 'user', content: 'こんにちは' }],
    stream: true,
  }),
});
```

Web アプリからブラウザー経由で直接呼び出すと CORS に当たります。そのページのオリジンを
`config/config.json` の `security.allowedOrigins` に追加してください：

```json
{ "security": { "allowedOrigins": ["http://192.168.1.50:3000"] } }
```

> モバイルアプリのフロントエンドに API キーをハードコードしないでください。自社バックエンド
> 経由で呼び出すか、利用者ごとに個別のキーを発行し失効手段を用意することを推奨します。

## その他の OpenAI 互換クライアント

Base URL と API キーを設定できるものであれば動きます。Open WebUI、LibreChat、Chatbox、
Continue.dev、LangChain の `ChatOpenAI`、LlamaIndex の `OpenAILike` など。

AGI BAR が現在実装しているエンドポイント：

| エンドポイント | 形式 | 説明 |
|---|---|---|
| `GET /v1/models` | OpenAI / Anthropic | モデル一覧（`anthropic-version` ヘッダーで形式が切り替わる） |
| `GET /v1/models/:id` | OpenAI | 単一モデル |
| `POST /v1/chat/completions` | OpenAI | 対話。`stream: true` に対応 |
| `POST /v1/completions` | OpenAI | 旧式のテキスト補完（内部で chat に変換） |
| `POST /v1/messages` | Anthropic | 対話。`stream: true` に対応 |
| `POST /v1/messages/count_tokens` | Anthropic | 入力トークンの推定 |
| `GET /v1/me` | AGI BAR | 自分のクォータと使用量を確認 |

2 つの形式は同一のパイプラインと同一のクォータを共有します —— `/v1/chat/completions` を
通っても `/v1/messages` を通っても、認証・時間帯・トークン枠・キューの優先度・記録は
すべて同じ仕組みです。

未実装：`/v1/embeddings`、`/v1/images`、`/v1/audio`。
これらを使うクライアントには `404 unknown_endpoint` が返ります。

## エラーコード対応表

クライアントに返るエラーはすべて OpenAI 形式で、`error.code` から原因を判断できます。

| code | HTTP | 意味 |
|---|---|---|
| `missing_api_key` | 401 | Authorization ヘッダーが無い |
| `invalid_api_key` | 401 | キーが存在しないか削除済み |
| `key_inactive` | 403 | キーが一時停止または失効 |
| `user_inactive` | 403 | 利用者アカウントが無効 |
| `expired` / `not_yet_valid` | 403 | 有効期間外 |
| `outside_time_window` | 403 | 許可された時間帯の外 |
| `weekday_not_allowed` | 403 | 本日は許可された曜日ではない |
| `rate_limit_exceeded` | 429 | RPM 超過 |
| `concurrency_limit` | 429 | 同時リクエスト数の超過 |
| `quota_exceeded` | 429 | トークンクォータを使い切った（hard ポリシー） |
| `request_too_large` | 413 | 1 回のリクエストが上限を超過 |
| `queue_full` / `queue_timeout` | 503 / 504 | キュー満杯、または待機タイムアウト |
| `all_models_unavailable` | 503 | ルート内のモデルがすべて利用不可 |
