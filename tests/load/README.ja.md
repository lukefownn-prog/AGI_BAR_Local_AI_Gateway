# M14 負荷テストと受け入れ

[繁體中文](README.md) ｜ [English](README.en.md) ｜ **日本語**

> 企画書の第 14 節「V1 受け入れ基準」および
> [Issue #2](https://github.com/lukefownn-prog/AGI_BAR_Local_AI_Gateway/issues/2) に対応します。

## 2 つのモード

| モード | 用途 | GPU |
|---|---|---|
| `--self-test` | **スクリプト自体**が壊れていないか検証。ゲートウェイ + 疑似モデルファーム内蔵 | 不要 |
| 通常モード | 実環境へ負荷をかける。これが M14 の**正式な受け入れ** | 必要 |

セルフテストモードは CI が毎回実行します（`tests/loadtest.test.mjs`）。受け入れ当日に
スクリプトが動くことを保証するためです。普段動かさない負荷テストスクリプトは、
2 回の受け入れの間にコード変更で壊れるのが最もよくあるパターンです。

## クイックスタート

まずスクリプト自体が正常か確認：

```bash
node tests/load/loadtest.mjs --self-test
```

実環境へ負荷をかける：

```bash
node tests/load/loadtest.mjs --url http://192.168.1.100:8787 --admin-pass "管理者パスワード" --users 10 --duration 60
```

## オプション

| オプション | 既定 | 説明 |
|---|---|---|
| `--url` | `http://127.0.0.1:8787` | ゲートウェイのアドレス |
| `--admin-user` | `admin` | 管理者アカウント |
| `--admin-pass` | — | 管理者パスワード（テスト利用者の作成に使用） |
| `--scenario` | `all` | `all` / `steady` / `burst` / `longrun` / `quota` |
| `--users` | `10` | 仮想利用者数。P0/P1/P2/P3 へ順番に割り当て |
| `--duration` | `30` | `steady` シナリオの継続秒数 |
| `--max-tokens` | `64` | リクエストごとの出力上限 |
| `--prompt-chars` | `400` | 入力の長さ |
| `--stream` | オフ | SSE ストリーミングを使用 |
| `--protocol` | `openai` | `openai` または `anthropic`（Claude Code の経路を検証） |
| `--json <ファイル>` | — | 後続分析用に生データを出力 |
| `--keep-users` | オフ | 終了後もテスト利用者を残す |

終了コード：**0** 合格／**1** 不合格／**2** 実行エラー。デプロイスクリプトに組み込めます。

## 4 つのシナリオ

**`steady`** —— クローズドループ。N 名の仮想利用者が継続的に負荷をかけます。受け入れ項目
「10 名が同時にリクエストを送り、キューが正常に機能し、リクエストの取りこぼしがない」と
「低優先度のリクエストが飢餓状態にならない」に対応します。

**`burst`** —— オープンループ。キュー容量をはるかに超えるリクエストを一気に流し込みます。
過負荷時にクラッシュ・タイムアウト・無言の消失ではなく、**429/503/504 をきれいに返す**ことを
確認します。

**`longrun`** —— 単発の長い応答。`server.requestTimeoutMs` で途中切断されないことを確認します。

**`quota`** —— RPM、1 回あたり上限、日次枠を極小に設定し、実際に効くことを確認して、
終了後に自動で復元します。

## 受け入れ判定

レポートの最後に一項目ずつ列挙されます。`✗` は要修正、`!` は観察値のみです。

| 判定 | 意味 | 致命 |
|---|---|---|
| リクエストの取りこぼしなし | すべてのリクエストが終局状態に到達 | ✓ |
| 全リクエストが request_logs に記録 | クライアントの `X-Request-Id` がサーバー記録で見つかる | ✓ |
| 想定外のエラーなし | エラーはキュー／クォータ由来のみ。500 や接続断は不可 | ✓ |
| トークン計量が一致 | サーバーとクライアントのトークン集計が許容範囲内 | ✓ |
| 低優先度が飢餓状態でない | P3 が少なくとも一部完了している | ✓ |
| 終了時にキューが空 | ポーリング後も空にならない = キュー枠のリーク | ✓ |
| 高優先度の待ち時間が短い | P0 の中央値 ≤ P3 | ✗ |
| 低優先度の最長待ち時間 | P3 の最長待ち時間が上限内 | ✗ |

性能系の判定は意図的に**致命扱いにしていません** —— マシンが変われば数字も変わり、
「この機体は遅い」を受け入れ失敗にすべきではないからです。

### 誤判定しやすい 2 点

**キューの排出はポーリングで判定し、即断してはいけません。** ゲートウェイは先に応答を
書き出し、キュー枠は `finally` で解放します（この順序が正しい —— 早く解放すると、
本件をまだ書き出している最中に次が通り、同時実行数が超過します）。そのためクライアントの
fetch 完了時点でも、サーバー側ではまだ実行中と数えられていることがあります。
スクリプトは 8 秒ポーリングし、それでも空にならない場合のみ失敗と判定します。

**`request_too_large` は想定内のエラーです。** `quota` シナリオが意図的に発生させます。

## 正式な受け入れの推奨手順

```bash
# 1. ベースライン：10 名の通常負荷で異常がないことを確認
node tests/load/loadtest.mjs --url http://<AI ホストの IP>:8787 --admin-pass "…" \
  --users 10 --duration 120 --json baseline.json

# 2. ストリーミング：実クライアントの多くはストリーミングで、レイテンシ特性が異なる
node tests/load/loadtest.mjs --url http://<AI ホストの IP>:8787 --admin-pass "…" \
  --users 10 --duration 120 --stream --json stream.json

# 3. Anthropic 経路（Claude Code）
node tests/load/loadtest.mjs --url http://<AI ホストの IP>:8787 --admin-pass "…" \
  --users 6 --duration 60 --protocol anthropic --json anthropic.json

# 4. フルロード：企画書の上限 50 名に近づける
node tests/load/loadtest.mjs --url http://<AI ホストの IP>:8787 --admin-pass "…" \
  --users 40 --duration 180 --json full.json
```

各ラウンドで同時に監視すべきもの：

- 管理ダッシュボードの **VRAM 使用率**（`queue.maxGlobalConcurrent` が高すぎると OOM）
- AI ホストの `nvidia-smi`
- `data/logs/agibar-YYYY-MM-DD.log` にエラーが出ていないか

観測した「平均待ち時間」と VRAM の余裕に応じて `queue.maxGlobalConcurrent` を調整し、
再実行してください。

## フェイルオーバー検証（手動介入が必要）

スクリプトは自分でモデルを停止しません。`steady` の実行中に、順位 1 のモデルサーバーを
手動で停止してください。次が観察されるはずです：

- リクエストが中断せずに成功し続ける
- 管理コンソールの「AI モデル」ページで順位 1 がオフラインになる
- 「ログ」ページにフェイルオーバーの印が現れる
- レポートの `steady` シナリオで p95 が上昇するが成功率は維持される

## 注意事項

- テスト利用者は必ず `loadtest-` で始まり、終了時に自動削除されます。途中で Ctrl+C しても
  削除されます。前回の残りがあれば、次回実行時に先に消去します。
- 利用者上限 50 名はハードリミットです。既存の利用者が上限に近い場合は `--users` を下げて
  ください。スクリプトが残り枠を先に計算し、明確にエラーを出します。
- テスト利用者のクォータは意図的に大きく設定してあります。負荷テストがクォータではなく
  キューに当たるようにするためです —— クォータの検証は `quota` シナリオの役目です。
- **本番稼働中のホストにフルロードテストを実行しないでください。** 実利用者を圧迫します。
